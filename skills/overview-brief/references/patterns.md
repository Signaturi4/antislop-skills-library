# Reusable patterns for overview documents

These came out of building a co-founder brief from ten scattered sources. They generalise to any "explain the whole thing" document.

1. **Audience decides scope and tier.** Fix the reader before reading sources; it sets the section set and what must be removed.
2. **Source -> section map.** Each source type feeds known sections. Missing source = skipped section, not filler.
3. **Narrow reading.** Headings first, then only the needed ranges; one knowledge-base question per section.
4. **Fact ledger.** Every number has a value, claim, source and date before it reaches the page. Research numbers keep their scope words.
5. **Claim headlines.** Each section's headline is the takeaway as a sentence. A reader skimming headlines only should get the story.
6. **Eyebrow + intro with provenance.** "From the team board (3 Nov)." Provenance in the first line, a source line at the end.
7. **Content shape -> component.** Principles: cards. Stages: ladder. Funnel: proportional bars from the ledger. Pricing: table. Systems: one diagram plus a status table (live / waiting / read-only). Rules: two-column list. Next steps: ordered list.
8. **Two registers.** Aspiring where the source is belief (vision, story); plain where it is fact (numbers, infra). One pull quote per aspiring section, taken verbatim from the source.
9. **Name the tensions.** Vision vs current revenue, plan vs actual, a bottleneck person. Put them in the text and in "open decisions".
10. **The open seat / the ask.** Overviews for a new person end with where they plug in and what to decide together.
11. **Anonymise by role and descriptor.** People -> roles, clients -> descriptors, internals -> functions. Same rule in HTML and Markdown.
12. **House tokens, both themes.** Pull fonts and colours from the project's design system; define a dark block; status colours separate from the accent.
13. **Two outputs.** HTML page for reading, Markdown copy for search and the knowledge base. Re-index the Markdown in the project memory if one exists.
14. **Update in place.** Same URL, rebuild ledger, change only moved sections, report the diff.
15. **Link down, not across.** The overview links to the detailed documents (plan, map, report) instead of copying them.
